# Portfolio thesis and application map

## Overall thinking
The common pattern across the recovered history is a capability-development loop, not a single navigation product:
observe -> normalize -> split -> execute -> verify -> correct -> gate -> merge -> learn.

The existing agentic-universe foundations emphasize observable success conditions, bounded workers, deterministic transforms, named artifacts, independent verification and reviewed knowledge updates. These are documented ideas, not proof of complete implementation or operational reliability.

## Three layers
1. Shared foundation: identity, provenance, contracts, tools/models, evaluation, human review, audit and controlled learning.
2. User-facing workstreams: staff automation, knowledge/evidence, forecasting, training/simulation, sensor data and readiness/resilience.
3. Research: coordination mechanisms, human-AI exploration and visual representations. Keep experimental agent organization separate from human authority and access policy.

## Proposed interfaces
SourceRecord: source_id, origin, acquired_at, rights_basis, handling_label, digest, validation_status.
TaskRecord: task_id, stream_id, owner, status, base_commit, input_sources, expected_artifact, acceptance, review.
ResultRecord: task_id, artifact, claims, evidence, tests, limitations, unresolved_questions, reviewer_decision.
These are design contracts, not production security mechanisms. The structural validator checks only the bundled planning records.
